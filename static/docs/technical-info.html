기술 문서 및 데이터 정책

치지직 알림 봇은 디스코드 본사의 보안 심사를 통과한 공식 인증 앱(Verified App)으로서, 프라이버시 보호와 고가용성 아키텍처를 최우선으로 설계되었습니다.

← 설명서로 돌아가기

1. 보안 및 개인정보 보호 정책

① Zero Privileged Intents: 기술을 통한 보안 증명

단순히 보안을 약속하는 것에 그치지 않고, 기술적으로 권한을 완전히 차단함으로써 보안을 증명합니다. 본 봇은 디스코드의 모든 민감한 권한(Privileged Gateway Intents)을 사용하지 않습니다(OFF).

  • Message Content Intent (OFF): 봇은 유저의 채팅 내용을 감시하거나 읽을 수 없습니다. 오직 슬래시 명령어(/)를 통해서만 상호작용합니다.
  • Server Members Intent (OFF): 서버의 전체 멤버 명부를 수집하거나 조회할 권한이 원천 차단되어 있습니다.
  • Presence Intent (OFF): 유저의 온라인 상태나 활동 정보를 일절 추적하지 않습니다.
[ 모든 Privileged Intents가 비활성화된 설정 화면 스크린샷 위치 ]

② 슬래시 명령어(Slash Commands) 전용 설계

모든 기능은 디스코드의 최신 API 규격에 맞춰 설계되었습니다. 봇은 유저가 직접 명령어를 입력할 때만 응답하며, 평상시에는 어떠한 데이터도 감시하거나 수집하지 않는 수동적 구조를 유지합니다.

③ 공식 인증 및 신원 검증 (Verified)

치지직 알림 봇은 디스코드의 보안 심사와 신원 검증을 통과하여 공식 인증 배지를 획득했습니다. 총 인원수 1만 명 이상 규모에서도 안정적으로 작동하며 디스코드 데이터 보호 정책을 준수합니다.

2. 최소 데이터 저장 및 관리

  • 최소 데이터 원칙: 알림 전송에 필수적인 디스코드 채널 ID와 스트리머 고유 ID(32자리 해시) 및 닉네임만을 저장합니다. 이름, 이메일, 멤버 리스트 등 개인 식별 정보(PII)는 수집하지 않습니다.
  • 격리된 보안 인프라: 모든 데이터는 Oracle Cloud 및 Google Cloud Platform의 독립 가상 환경 내 SQLite 데이터베이스로 관리되며 외부 네트워크 접근이 차단됩니다.
  • 즉각적인 데이터 파기: 사용자가 설정을 삭제하거나 봇이 서버에서 퇴장할 경우 해당 서버 관련 모든 데이터는 즉시 영구 파기됩니다.

3. 글로벌 분산 프록시 및 네트워크 안정성

보안성뿐만 아니라 알림의 신속성과 가동률을 극대화하는 분산 네트워크를 운영합니다.

  • 글로벌 5-Node 분산 프록시 아키텍처: 한국(GCP-Seoul, GCP-Direct), 해외(Oracle Proxy 1, 2), 글로벌 엣지(Cloudflare Workers) 5개 독립 노드가 라운드 로빈(Round-Robin) 방식으로 API 요청을 분산 처리하여 단일 서버 장애와 429 제한을 방어합니다.
  • 방대한 유동 IP 풀 활용: GCP 서울 리전(asia-northeast3) 약 19만 개(193,536개) 및 Cloudflare 약 152만 개(1,524,736개)의 글로벌 IPv4 네트워크를 기반으로 차단 및 쓰로틀링에 유연하게 대응합니다.
  • 무중단 자동 장애 조치(Zero-Downtime Failover): 특정 노드에서 타임아웃이나 차단 응답 발생 시 즉각 대기 노드로 요청을 우회(Retry)하여 알림 누락을 방지합니다.
  • 트래픽 변조(Jitter) 기술: 매 요청 사이에 0.1s~0.3s 무작위 난수 지연을 부여해 기계적 패턴 탐지를 회피합니다.
[ 5개 글로벌 노드의 실시간 건강 상태(Health Check) 모니터링 스크린샷 위치 ]

4. Multi-Cloud 고가용성(HA) 및 데이터 동기화

2026년 5월 1일 적용된 아키텍처를 통해 24/365 무중단 운영을 보장합니다.

① High Availability (HA) 아키텍처

  • Active-Passive Failover: 메인 노드(GCP)와 예비 노드(Oracle Cloud)가 상호 감시 체계를 유지하며, 메인 장애 시 30초 이내 예비 노드가 자동으로 역할을 승격(Promotion)합니다.
  • Multi-Cloud Infrastructure: 서로 다른 클라우드 벤더 분산으로 특정 벤더 전역 장애 상황에도 서비스 연속성을 보장합니다.

② 실시간 데이터 동기화 엔진

  • Query Mirroring Technology: Master 노드의 모든 DB 변경(INSERT, UPDATE, DELETE)을 REST API로 Slave 노드에 즉시 미러링하여 99.9% 이상 데이터 일치율을 유지합니다.
  • Boot-time Full-Sync: 재시작 시 상대 노드로부터 전체 스냅샷을 수신하여 오프라인 기간 누락을 자동 보정합니다.

③ 중복 알림 및 상호작용 충돌 방지

  • Startup Role Negotiation: 부팅 시 Master 존재 여부를 확인해 스스로 Stand-by 모드로 진입하여 중복 발송을 차단합니다.
  • Smart Interaction Handling: Slash Command 요청 시 Master 노드만 응답하도록 제어해 Unknown Interaction 에러를 방지합니다.

5. 치지직 지역 제한(9004) 우회 및 로직 최적화

2026년 5월 3일 도입된 서울 리전 프록시(GCF)를 통해 국내 전용 방송 설정으로 인한 500/9004 에러를 해결했습니다.

  • 서울 리전 전용 중계 노드: Google Cloud Functions(asia-northeast3)를 활용해 한국 내 IP(193,536개)로 안정적으로 국내 접속을 처리합니다.
  • 지능형 API 라우팅: 지역 제한 우회가 필요한 라이브 API는 서울 프록시를 최우선 사용하고, 커뮤니티 API는 기존 분산 노드를 활용하도록 이원화했습니다.
  • 무중단 페일오버: 서울 프록시 실패 시 다음 가용 노드로 자동 전환됩니다.

7. 권한 사용의 정당성

초대 권한(150528)은 오직 서비스 제공을 위한 기술적 필수 용도로만 사용됩니다.

  • 채널 보기: 알림을 보낼 채널을 인식하기 위해 필요합니다.
  • 메시지 보내기 & 링크 첨부: 치지직 방송/커뮤니티 알림 전송 및 썸네일 임베드 포함을 위해 사용됩니다.
  • 모두 멘션하기: 알림 전송 시 @everyone, @here 또는 특정 역할 멘션을 위해 사용됩니다.
